## 1. Введение

Передача данных по виртуальным топологиям — отдельная важная тема в MPI.  
Кольцо (ring) — одна из самых простых топологий: у каждого процесса есть два соседа, “левый” и “правый”.

В этой работе нужно реализовать передачу данных от произвольного процесса-источника (`src`) к процессу-получателю (`dest`) по кольцу:

- в **SEQ-версии** разрешено использовать весь функционал MPI, в том числе декартовы топологии;
- в **MPI-версии** топологию нужно задать вручную, без `MPI_Cart_create` и `MPI_Graph_create`.

Цель работы — реализовать обе версии (SEQ и MPI), проверить корректность с помощью тестов и посмотреть время выполнения на разных числах процессов.

## 2. Постановка задачи

**Входные данные**:

```cpp
struct InType {
  int src;    // процесс-источник
  int dest;   // процесс-получатель
  int count;  // размер передаваемого массива
};
````

**Выход:** одно число `int`:

* `1` — данные успешно дошли от `src` до `dest`;
* `0` — ошибка.

Ограничения:

* `0 ≤ src, dest < size`;
* `count > 0`;
* корректная работа должна быть обеспечена при любом количестве процессов: от 1 и выше.

Передаваемые данные — массив вида:

```cpp
buffer[i] = i + 1;
```

## 3. Последовательная реализация (SEQ)

### Логика алгоритма

SEQ-версия использует виртуальную топологию MPI:

* построение кольца через `MPI_Cart_create`;
* поиск соседей через `MPI_Cart_shift`.

---

### **1. Инициализация и проверка входных данных**

```cpp
const bool valid =
    (0 <= src && src < size) &&
    (0 <= dest && dest < size) &&
    (count > 0);

if (!valid) { GetOutput() = 0; return true; }
if (src == dest) { GetOutput() = 1; return true; }
```

Если параметры вне диапазона — задача завершается.
Случай `src == dest` обрабатывается сразу.

---

### **2. Создание кольцевой топологии через Cart**

```cpp
MPI_Comm ring_comm = MPI_COMM_NULL;
int dims[1]    = { size };
int periods[1] = { 1 };
MPI_Cart_create(MPI_COMM_WORLD, 1, dims, periods, 0, &ring_comm);
if (ring_comm == MPI_COMM_NULL) { GetOutput() = 0; return true; }
```

Создаётся кольцо размера `size`.

---

### **3. Инициализация данных у источника**

```cpp
std::vector<int> buffer(count);
if (rank == src) {
  for (int i = 0; i < count; ++i)
    buffer[i] = i + 1;
}
```

Источник заполняет буфер числами `1..count`.

---

### **4. Определение, участвует ли процесс в передаче**

```cpp
int clockwise_distance = (dest - src + size) % size;
int offset_from_src    = (rank - src + size) % size;
bool is_on_path        = (offset_from_src <= clockwise_distance);
```

Процесс участвует, только если он лежит на пути от `src` до `dest` по часовой стрелке.

---

### **5. Получение соседей и передача данных**

```cpp
int prev_cart, next_cart;
MPI_Cart_shift(ring_comm, 0, 1, &prev_cart, &next_cart);
```

Дальше:

```cpp
if (rank == src) {
  MPI_Send(buffer.data(), count, MPI_INT, next_cart, 0, ring_comm);
} else {
  MPI_Recv(buffer.data(), count, MPI_INT, prev_cart, 0, ring_comm, &status);
  if (rank != dest)
    MPI_Send(buffer.data(), count, MPI_INT, next_cart, 0, ring_comm);
}
```

Источник отправляет сообщение соседу, каждый промежуточный процесс пересылает дальше.
Получатель только принимает и не отправляет.

---

### **6. Проверка корректности данных на получателе**

```cpp
int local_ok = 1;
if (rank == dest) {
  for (int i = 0; i < count; ++i)
    if (buffer[i] != i + 1) { local_ok = 0; break; }
}
```

---

### **7. Коллективная агрегация результата**

```cpp
int global_ok = 0;
MPI_Allreduce(&local_ok, &global_ok, 1, MPI_INT, MPI_LAND, MPI_COMM_WORLD);
MPI_Comm_free(&ring_comm);
GetOutput() = global_ok;
```

Если получатель получил корректные данные — все процессы возвращают `1`.

---

### **Сложность**

* **Время:** `O(N)` — сообщение проходит через `N` процессов.
* **Память:** `O(count)` — буфер хранится на каждом участнике пути.

## 4. Параллельная реализация (MPI)
MPI-версия делает то же самое, что и `SEQ`, но топология формируется вручную.
Вместо `MPI_Cart_create` и `MPI_Cart_shift` используются соседи:
```cpp
int prev = (rank - 1 + size) % size;
int next = (rank + 1) % size;
```
Дальше логика идентична `SEQ`:
* `src` заполняет буфер;
* процессы, находящиеся на пути от `src` до `dest`, принимают данные от `prev` и пересылают `next`;
* `dest` проверяет содержимое буфера;
итог собирается через `MPI_Allreduce`.

## 5. Реализация (общее описание)

В проекте реализованы два класса:

```cpp
GalkinDRingSEQ
GalkinDRingMPI
```

Они наследуются от общего шаблона:

```cpp
ppc::task::Task<InType, OutType>
```

и проходят одинаковые этапы:

* `ValidationImpl()` — проверка параметров;
* `PreProcessingImpl()` — обнуление выходного значения;
* `RunImpl()` — основная логика передачи;
* `PostProcessingImpl()` — финализация.

### Валидация

Условие валидности входа:

```cpp
bool ValidationImpl() {
  const auto& in = GetInput();
  int size = 1;
  MPI_Comm_size(MPI_COMM_WORLD, &size);

  bool src_in_range  = (0 <= in.src) && (in.src < size);
  bool dest_in_range = (0 <= in.dest) && (in.dest < size);
  bool count_ok      = (in.count > 0);

  return src_in_range && dest_in_range && count_ok;
}
```

### Проверка результата

```cpp
int local_ok = 1;
if (rank == dest) {
  for (int i = 0; i < count; ++i) {
    if (buffer[i] != i + 1) {
      local_ok = 0;
      break;
    }
  }
}
```

```cpp
int global_ok = 0;
MPI_Allreduce(&local_ok, &global_ok, 1, MPI_INT, MPI_LAND, MPI_COMM_WORLD);
GetOutput() = global_ok;
```

У всех процессов в итоге `GetOutput()` одинаковый.

## 7. Результаты
### 7.1 Проверка корректности
Обе версии (SEQ и MPI):
* проходят все функциональные тесты PPC;
* корректно обрабатывают неверный ввод;
* дают одинаковый результат на всех процессах;
* успешно повторно выполняют одну и ту же задачу.
Получатель всегда получает массив `[1, 2, …, count]`, поэтому итоговый `GetOutput()` на всех рангах равен `1`.

## 8. Заключение
В рамках работы реализованы две версии алгоритма передачи данных по кольцу:
* SEQ-версия использует MPI_Cart_create и MPI_Cart_shift для построения кольцевой топологии.
* MPI-версия реализует кольцо вручную (что является требованием варианта) — без MPI_Cart_create и без MPI_Graph_create.
Обе версии:
* корректно передают данные между любыми двумя процессами;
* проходят все тесты PPC;
* одинаково обрабатывают корректный и некорректный ввод;
* дают предсказуемые результаты при изменении числа процессов.
Рост времени при увеличении числа процессов объясняется тем, что сообщение проходит больший путь по кольцу — это подтверждается экспериментально.
